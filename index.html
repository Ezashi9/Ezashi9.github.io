Log Hunter

Reads SSH server logs and detects brute-force attacks, username spraying and suspicious successful logins.

On real server logs: 532 failed logins from 24 IPs; flagged 6 brute-force sources, one making 147 attempts in 5 minutes. Checking it against the raw data exposed two parsing gaps that were hiding attacks, both fixed and tested.

SOC-ready: every detection is mapped to MITRE ATT&CK (T1110 Brute Force, T1078 Valid Accounts) and published as a Sigma rule, the vendor-neutral format SIEMs import, validated with the official Sigma tools.

Tested like a SOC would: 10 labelled attack and normal-activity scenarios. The first version passed 6; testing exposed blind spots for IPv6, low-and-slow and distributed attacks plus a false alarm, all fixed (now 10/10).

IOC Enricher

Checks attacker IP addresses against AbuseIPDB threat intelligence and gives each a verdict.

Finding: attackers from older logs had dropped out of threat feeds entirely, while 9 of 10 IPs attacking SSH that week scored 100/100. Threat intelligence goes stale. Never sends internal IPs to third parties; API key kept out of code.

Python · threat intelligence · APIs · secrets handling

Home SOC Dashboard

A web dashboard presenting Log Hunter's detections and the threat-intelligence verdicts.

Security focus: attackers choose the usernames that appear in logs, so the dashboard is hardened against log-injection XSS (output escaping, safe rendering, strict Content Security Policy) and was tested with malicious payloads in a real browser.

JavaScript · web security · XSS · data visualisation

Live Threat Feed

A pipeline that runs itself every day: pulls current attacker data from SANS DShield and blocklist.de, checks it against AbuseIPDB and publishes it.

Finding: the same check flagged 24 of 25 SSH password guessers as malicious, but 0 of the 25 busiest sources on DShield, which are mostly scanners. No single feed sees everything.

Email security, risk and privacy

Phish Triage

Analyses a suspicious email like a junior SOC analyst: sender authentication, lookalike domains, deceptive links, dangerous attachments and brand impersonation. Never opens links or attachments.

Tested on real phishing: caught 59.3% of a held-out sample of real phishing emails with 0.9% false alarms on 2,500 legitimate ones, up from 40.3%. Found that most missed phishing passed SPF, DKIM and DMARC from attacker-owned domains. Evaluation runs in the cloud so live samples never touch my PC.

Python · email security · phishing · evaluation methodology

Breach Check

Checks whether a password has appeared in a data breach without the password ever leaving your device.

How: k-anonymity. Only the first 5 characters of the password's SHA-1 hash are sent to Have I Been Pwned; the browser compares the ~2,000 returned hashes itself. Verified in a browser that the password appears in no network request.

JavaScript · Python · cryptographic hashing · privacy by design

How I build

  • Tested on every change. Each project's tests run automatically on GitHub; the badges above show the current result.
  • Scanned for security problems. GitHub's CodeQL code scanning, Dependabot alerts and secret scanning with push protection are on for every repository.
  • Secrets never in code. API keys live in ignored local files or encrypted CI secrets.
  • Dependencies pinned to exact commits, so a tampered release can't slip into a build.
  • Checked against reality. Every result was verified against the raw data or in a real browser, and each README explains what went wrong along the way, not just what worked.
  • Built with AI assistance. I use an AI coding assistant (Claude) to build faster, and I make sure I understand and can explain every design decision in these projects.
